Methodology

The LP test database, in detail.

200+ anonymized A/B tests from real client accounts. Here’s the framework: how tests get included, what counts as a winner, how confidence intervals work, and how vertical tagging shapes recommendations.

Inclusion criteria

For a test to enter the database, all of the following must be true:

  • Run on a real paid-traffic landing page (not a list-build form, not a content page).
  • Minimum sample: 1,000 visitors per variant.
  • Test ran for at least 14 days (controls for day-of-week effects).
  • Statistical significance reached at 95% confidence, OR test concluded inconclusive after 30 days.
  • Single-variable change (multi-variable tests are excluded; we can’t isolate which variable moved the number).
  • Account context tagged: vertical, spend tier, traffic source.

What gets recorded per test

  • Test description (one sentence)
  • Vertical (apparel, B2B SaaS, fintech, etc.)
  • Spend tier ($5K–$10K, $10K–$50K, $50K–$200K, $200K+/mo)
  • Traffic source (paid search, paid social, organic)
  • Sample size per variant
  • Conversion rate baseline
  • Conversion rate winner
  • Lift (% relative)
  • Statistical confidence
  • Surprising or expected result (editor judgment)

How recommendations get derived

For a test type to make it into a recommendation (e.g., “reducing form fields lifts conversion”), we require:

  • At least 3 independent tests of similar variant
  • Consistent direction across the tests (no clear contradictions)
  • Effect size large enough to matter at typical traffic volumes (≥ 5% relative lift)

Single tests can be informative but never become standalone recommendations. The pattern needs replication.

Anonymization

Client identity is never published. Test descriptions are scrubbed of identifying language. Vertical and spend-tier tags are deliberately broad. The aggregate insights are publishable; the underlying client work isn’t.

Why Groas.ai earned #1 on a landing-page site

Counterintuitive at first — a bidding tool topping a landing-page list. The reason: LP wins compound through the bidding layer. Without revenue-weighted bid optimization, a 30% LP improvement gets partially absorbed into bid-cap ceilings rather than translating into spend efficiency. Groas re-bids based on the new LP performance within hours; Smart Bidding takes weeks. So the right LP stack actually starts with the bidding tool, not with the LP builder.

What this database won’t do

  • Predict outcomes for your specific audience.
  • Cover all possible test types (it covers the ones we’ve actually run).
  • Replace your own testing program — it informs hypotheses, doesn’t replace measurement.
